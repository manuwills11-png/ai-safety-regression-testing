# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary user: an ML engineer deploying fine-tuned open-source LLMs — specifically, teams fine-tuning or reconfiguring Gemma 4 checkpoints. They ship changes to a model regularly and have no reliable way to know whether a given deploy silently weakened its safety guardrails until a jailbreak surfaces publicly or via a security researcher.

Secondary audience: whoever reviews a failed CI check on their team (may not be the same person who triggered the deploy) — they need to understand *what* regressed and *why* fast, from the Safety Diff and Attack Replay artifacts alone, without re-running anything.

## Product Purpose

CI regression testing for AI safety. On every deploy, an attacker LLM (Gemma 4) iteratively red-teams a target model (also Gemma 4, in a safe vs. weakened configuration), a judge LLM scores each attempt, and a regression engine diffs the result against the last known-good archive. If a risk category that used to be defended flips to broken, the build fails — the same reflex engineering teams already have for a broken unit test, applied to model safety instead of code correctness.

## Positioning

Existing tools sit at one of two poles: static probe batteries (Garak, PyRIT, and CI-gated scanners built on fixed test lists) that never discover a jailbreak nobody already wrote down, or adaptive discovery research (PAIR, TAP, AutoDAN-Turbo) that finds novel attacks but isn't wired into CI, versioned, or regression-tracked. This product is the combination neither side has shipped: adaptive discovery (attacker LLM + judge feedback loop) wired directly into a CI regression gate.

## Operating Context

Used via a CLI (`run`, `diff`, `report`, `replay`) and a GitHub Action that gates pushes/PRs. The two surfaces in scope for this design pass are static, self-contained HTML reports generated by the CLI:

- **Safety Diff** (`safety_diff.html`) — the category-by-category ✓/✗ comparison between two archives; the product's signature screen, meant to answer "did this deploy make the model less safe?" in seconds.
- **Attack Replay** (`replay.html`) — drill-down into one specific attack: the adversarial prompt, the target's response, the judge's reasoning, and a one-word Root Cause label.

Both are opened directly as `file://` pages locally, or downloaded/viewed as CI run artifacts after a failed build — not embedded in a larger web app, no server, no login. Often opened by someone who just got paged by a red CI check and wants the answer fast.

## Capabilities and Constraints

- Inline CSS only, zero external requests (fonts, scripts, CDNs) — must render identically offline as a downloaded CI artifact.
- Renders live, adversarial, model-generated content (attack prompts, target responses, judge reasoning) that must be HTML-escaped before display — this is a security requirement, not a style choice.
- Fixed risk-category vocabulary: `roleplay_bypass`, `prompt_injection`, `multi_turn_escalation`, `tool_misuse`.
- Verdict states: `pass`/`fail` per attack; confidence `low`/`medium`/`high`.
- Generated by Python (`src/render.py`), consumed by a CLI and CI — no build step, no bundler.

## Evidence on Hand

- Real synthetic fixtures with a deliberate 2-category regression (`examples/archive_v1_synthetic_test.json`, `archive_v2_synthetic_test.json`).
- Real live-discovery archives from actual Gemma 4 runs (`examples/archive_v1_cached.json`, `archive_v2_cached.json`).
- A real GitHub Actions run where this exact regression gate caught a genuine safety regression and failed the build (referenced in DEMO.md).

## Product Principles

1. Read like a tool a working engineer already trusts under pressure — GitHub's Security tab, a Sentry issue, a Snyk finding — not a marketing surface or a generic AI-tool template.
2. The Safety Diff is the single highest-stakes screen: it must be scannable in seconds by someone who just got paged, not admired.
3. Never compromise the HTML-escaping of adversarial content for a visual effect — the content being displayed is, by design, hostile input.
4. No network dependency in the rendered output — it must be trustworthy and complete as a static, offline artifact.

## Accessibility & Inclusion

`prefers-reduced-motion: reduce` must disable all entrance/attention animations — established requirement carried forward from the prior implementation.
